# Shared backend interfaces v2

Package imports `backend.app`. API base `/api/v2`; no v1 handler mounted by default. Router modules export `router` (APIRouter) without `/api/v2` prefix.

`db.py`: Base, get_db() -> SQLAlchemy Session (request transaction commits on successful return; rollback on exceptions), SessionLocal, engine. PostgreSQL only; DATABASE_URL required at runtime. Domain modules import Base and append mapped models in models_<group>.py. No duplicate shared tables.

`auth.py`: Actor(user_id,username,display_name,organization_id,facility_id,roles:set,permissions:set,patient_scope:str|None,session_id), current_actor(request,db=Depends(get_db)), require(actor,permission), require_domain(actor,'Dxx',write=False), scoped_patient(db,actor,id,lock=False), scoped_encounter(db,actor,id,lock=False). Requires current server membership every request; all mutations cookie+CSRF verified. Domain transaction entry call revalidate_actor(db,actor) locking User to serialize admin revoke against mutations. Scoped helpers return models, 404 outside scope. Clinical actor has assigned facility; portal actor bound one patient. No system-admin clinical approve.

`common.py`: uid(), utcnow(), canonical(data)->str, digest(data)->SHA256, serialize(model)->dict (timestamps ISO, Decimal string), audit(db,actor,domain,entity_id,action,details=None), check_version(model,expected), begin_operation(db,actor,key,operation,payload)->stored response or None, finish_operation(...,response), transition(record,target,allowed,version). Operations lock shared actor row then key via PostgreSQL advisory transaction lock to serialize duplicate-key races. Every domain has own relational schema and explicit DTO/actions.

Core models in models.py: Organization(id,name), Facility(id,organization_id,name), Department(id,organization_id,facility_id,name), Location(id,organization_id,facility_id,name,kind), User(id,organization_id,username,display_name,password_hash,status,version), Membership(id,user_id,facility_id,role,active), UserPatientScope(user_id,patient_id), SessionRecord(id,user_id,token_hash,csrf_hash,expires_at,revoked_at), Patient(id,organization_id,facility_id,display_name,birth_date,sex,status,version), PatientIdentifier(id,patient_id,organization_id,issuer,value), Encounter(id,organization_id,facility_id,patient_id,department_id,status,kind,version), Task(id,organization_id,facility_id,patient_id,encounter_id,domain,kind,title,status,version,assignee_id), Document(id,organization_id,facility_id,patient_id,encounter_id,title,status,version,current_version_id), DocumentVersion(id,document_id,version,content,content_hash,created_by), AuditEvent(id,organization_id,actor_id,domain,entity_id,action,details,created_at), Operation(actor_id,key,operation,payload_hash,response). Shared row IDs are string UUIDs (seed IDs readable). Money NUMERIC(18,2), quantity NUMERIC(18,3), aware UTC times.

Auth endpoints: POST auth/login {username,password} -> {user:{id,username,display_name,organization_id,facility_id,roles,permissions,patient_scope},csrf_token,expires_at}; GET auth/me same; POST auth/logout; POST auth/context {membership_id}. Mutation header X-CSRF-Token. Lists return {items:[]}; entities plain DTO. GET /home is permission-filtered worklist and counters. All business mutations header Idempotency-Key, expected version in body on existing records.

Core POST /patients {display_name,birth_date?,sex,identifier,issuer='LOCAL'}; PATCH /patients/{id} {version,display_name,birth_date?,sex}; POST /patients/{id}/transition {version,target}. GET /patients?q and /patients/{id}. POST /encounters {patient_id,department_id?,kind='OPD'}; POST /encounters/{id}/transition {version,target,reason?}; GET /encounters?patient_id.
POST /tasks {patient_id,encounter_id,domain,kind,title}; GET /tasks?encounter_id; POST /tasks/{id}/transition {version,target}.
POST /documents {patient_id,encounter_id,title,content}; POST /documents/{id}/revise {version,content,reason}; POST /documents/{id}/transition {version,target,content_hash}; GET /documents?encounter_id; GET /documents/{id}/versions.
POST /proposals {task_id,document_id,scenario='success'}; GET /proposals?task_id; POST /proposals/{id}/review {version,action_hash,decision:'edit'|'approve'|'reject',edited_text?}; POST /proposals/{id}/commit {version,action_hash}. Proposal DTO embeds action:{text}, evidence:{document_version_id,content_hash,encounter_version}, status/version/action_hash. GET /results?encounter_id; GET /runs?task_id; GET /audit?entity_id.

## Integrated implementation notes

Authoritative source now backend/app/*.py and generated OpenAPI. Actor also carries care_patient_ids (None for facility-based assignments; explicit set for clinician/nurse). Role permissions are relational role_permissions rows, recomputed with credential checks. Operation stores org/facility/authorization fingerprint and rejects old-scope replay. Auth service mutation entry takes organization advisory authorization fence before any row locks; function-scoped dependencies commit before response. See backend/README.md for tradeoffs and tests.

D07 core /orders includes rehab kind, catalog, sign/acknowledge/start/complete/cancel/revise. Destination task domains labD10,medicationD08,imagingD11,procedureD12,rehabD16. Destination domain services validate source order version. Direct generic task transition cannot complete order-bound tasks.

D22 read without documents.content returns metadata and nullcontent; versions endpoint requires documents.content. documents.export is separately declared for narrative export. D24.export,D33.export,D36.export are explicit permissions. D34 admin care assignment route POST /admin/users/{id}/care-assignments {patient_id,active}; /admin/security-events lists bounded rejected-request metadata.

AI tasks must belong to D37 and kind document_review/imaging_review/dr_review. Proposal evidence additionally binds task_version. Result DTO includes proposal_version alias, operation_key and action_hash for exact UI recovery. GET /operations/{key} checks the current authorization fingerprint, with static /operations/jobs and /operations/health registered first.
