# Implemented demo API v1

This file describes the actual stdlib/SQLite implementation, not a planned production API.
Run from package root: `python -m src.his_poc.server`. Python 3.11+ target, verified on Python 3.12.14; no pip packages required for backend runtime. Loopback only, default port 8080. `HIS_DB_PATH`, `HIS_PORT`, `HIS_DEMO_TOKEN` are read directly from environment; `.env` is not auto-loaded.

All `/api/v1/*` routes require bearer authentication. Seeded `demo-reviewer-token` maps to reviewer-demo; `demo-viewer-token` maps to viewer-demo. These are deliberately public synthetic authentication fixtures, not credentials for any external service. Production identity/session management is NOT_IMPLEMENTED. Never expose this server to a network or load real patient data.

| Method / path | Request | Response |
|---|---|---|
| GET / | none | Thai demo HTML, no external assets |
| GET /health | none | status, demo, inference_profile; liveness only, not live-provider readiness |
| GET /api/v1/context | bearer | fixed p-demo/e-demo scoped document, evidence, proposals, persisted results, runs, reviews, tasks, immutable proposal versions and audit |
| POST /api/v1/proposals | patient, encounter, scenario optional, data_class optional | demo, run_id, outcome, proposal on success; otherwise error/reason |
| POST /api/v1/reviews | proposal_id, version, action_hash, decision, edits optional | review_id, updated proposal |
| POST /api/v1/commits | proposal_id, version, action_hash, idempotency_key | result, replayed |
| POST /api/v1/documents | patient, encounter, expected_version, content | new version |

`scenario` is success/timeout/failure/invalid/abstain. These simulate provider paths; no actual timeout or cancellation transport is implemented. `data_class` must be synthetic. Only explicit mock_demo+mock profile resolves; every live provider fails closed without network calls. Config is read from config/runtime.json; only inference_profile and provider affect this runtime. Other registry/policy files are design inputs for later adapters, not silently claimed enforcement. Data classification currently depends on the synthetic-only demo perimeter, not an automatic PHI detector.

POST validates before service dispatch using src/his_poc/request_validation.py. Body must be an object with the exact required/optional fields in the corresponding request schema. Unknown fields, nested extra document properties, invalid UTF-8, duplicate JSON keys, nonfinite constants, Boolean/nonpositive/nonintegral versions and non-hex/non-64-character action hashes are rejected with 400 before mutation. Integral JSON numeric versions such as 1.0 normalize to int 1 before comparisons/idempotency hashing. Content-Type must be application/json; exactly one Content-Length of 1–65536 bytes, no Transfer-Encoding; body-read timeout is 5 seconds.

Review edits are allowed only for decision=edit (nonblank string, at most 4000 characters). Approve/reject must omit edits entirely, including null; this prevents ambiguous approval of unsaved changes.

Document content requires text, and optionally author/signed_at, all strings. Mock computes missing author/signed_at as deterministic fixture output. This is a software demonstration of completeness, not clinical completeness.

Proposal fields: id, patient, encounter, version integer, action (JSON-encoded string), action_hash, snapshot (JSON-encoded string), status, expires (UTC epoch seconds), run_id (AI run provenance). Action object contains kind=document_completeness, summary, missing_fields. Snapshot contains encounter_version, document_id, document_version, document_hash, locator=document.content, data_class=synthetic. Hash is SHA256 of UTF-8 JSON, keys sorted, separators `(',', ':')`, ensure_ascii=False. The JSON strings reflect SQLite row responses; future typed DTO conversion is a versioned API change.

States: pending -> approved/rejected; action snapshots are retained in proposal_versions; edit requires a nonempty summary string, stores review edits, increments proposal version/hash and remains pending; approved -> committed. Approval binds exact version/hash. Expiry is creation+900 seconds. Review and commit verify current encounter open/version, document version/hash, scope and permission. Commit also rechecks approving reviewer's current permission. Single SQLite BEGIN IMMEDIATE transaction writes result, only the explicitly named task-demo completion, idempotency record and audit together. The demo target is p-demo/e-demo/task-demo; it is checked before/after inference, review and first commit. Missing, closed, cancelled or mismatched target fails without a result. A completed task does not accept another proposal; use a new DB for a new journey. Restart never reopens or recreates a deleted target. This is a deliberately bounded demo, not generic multi-task routing. A replay of a completed request rechecks current caller scope and returns original result; it does not revalidate changed clinical context because no new write occurs. A new key for an already committed proposal is rejected. Same key/different actor or payload is conflict. DB uniqueness prevents duplicate result per proposal.

After inference the service rechecks current authorization and input snapshot before proposing; invalidated attempts persist as failed runs without a proposal. Non-object provider responses persist as INVALID_PROVIDER_OUTPUT. Runs persist failed/timeout/abstained outcomes, observed wall latency, provider/model fixture revision, demo=true, and nullable abstain_reason bounded to 1000 characters. Immediate response, persisted run and ai_run audit use the same bounded reason. Existing v0.1 rows retain null through an additive migration; see MIGRATIONS.md. Cost is NULL and usage is JSON null: token costs are not invented. Provider failure yields HTTP 200 with outcome failed/timeout/abstained; callers must inspect outcome, not HTTP alone. Domain rejections return HTTP 400/401/403/404/409 with error code. Exceptions return generic 500 without credentials/body echo.

Tables: patients, encounters, users, documents, tasks, proposals, proposal_versions, reviews, results, idempotency, runs, audit. User->patient scope is one seeded assignment; full RBAC/ABAC, multi-tenant administration, migrations, tamper-evident audit, production backup/restore, asynchronous cancellation, and actual provider transport remain backlog work. Audit is application-append-only, not cryptographically tamper-proof. Authorization denials are returned but not persisted as audit in this minimal implementation; audit security events is a follow-on task. No actual clinical record signing, payer transaction or monetary ledger occurs.

Validation: `python -m unittest discover -s tests -v`; `python scripts/demo_journey.py <new-db-path>` prints persisted evidence. Tests include HTTP journey, negative auth, tool scope, concurrent duplicate retries, key conflict, reviewer edits, rejection, expiry, revoked permission, stale document/context, mock failures/timeout/abstention, restricted data and disabled live routes. Legacy HTML behaviors are additionally tested with Node VM/DOM/fetch doubles, which are not browser or visual QA. Current React/browser evidence is recorded separately in VALIDATION_REPORT.md.

## v0.2 contract coverage

OpenAPI description revision 1.0.1 retains `/api/v1` namespace. All implemented success/error responses now reference schemas, including health, context, proposal, review and document-update envelopes. `contracts/v1/fixtures/workflow.json` contains 27 named frozen HTTP captures. `python contracts/check_contracts.py` validates 23 schema definitions, 2 examples, 176 request-schema parity cases, 27 fresh local HTTP responses and 27 frozen responses. These counts are from this round; they do not claim formal/exhaustive schema equivalence, specialist execution or live inference. Use `--write-fixtures` only for an intentional contract revision and review the resulting diff.

Task-specific 409 codes: UNSUPPORTED_TASK_SCOPE, TASK_NOT_FOUND, TASK_CONTEXT_MISMATCH, TASK_NOT_OPEN. Other errors are specified in OpenAPI. Runtime still uses stdlib HTTP and demo auth; no framework or identity-provider migration occurred in this increment.
