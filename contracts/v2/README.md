# API v2

Authoritative implementation: `backend/app`; exported `openapi.json` generated by `python scripts/export_contracts_v2.py`. Domain shared routes validate against dedicated models; see clinical-inputs.json/erp-inputs.json and catalog metadata for individual domain actions. These are versioned contracts, not proof of completed acceptance.

All API paths start `/api/v2`. Server-backed session HttpOnly cookie, `X-CSRF-Token` for authenticated writes, and `Idempotency-Key` for business mutations. Expected version on existing-record actions. Unknown fields and invalid state/reference are rejected before transaction completion. Actor and scope come from server; client patient_id must match encounter ownership.

Success returns authoritative updated entity/operation data. Failure status409 for conflicts and422 for invalid body is definitive when application contract marks no commit; lost transport/5xx remains unknown until identity-matching replay/read-back. UI must not generate new keys to guess that unknown writes failed. Financial quantities serialize Decimal as strings.

Default application does not mount `/api/v1`; old public bearer demo tokens do not authenticate new routes. Legacy src tests run a separate process/database and must never be exposed as a backdoor to v2. v1 schemas and frozen responses are retained unchanged for regression/import reference. No v1 client can assume it works against v2 without authentication/DTO migration.

`schema-reference.sql` and DATA_DICTIONARY are generated from loaded models. Migrations remain authoritative for operational DDL and additional triggers/constraints. Do not apply reference SQL as an upgrade.
